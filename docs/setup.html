Zgradonačelnik.rs — Setup tutorijal (KORAK PO KORAK)

Ovo je “klik‑po‑klik” uputsvo da povežeš sve ključeve i servise koje koristimo u projektu: Supabase, Google OAuth (login), Vercel, Resend (OTP email), Turnstile (CAPTCHA), Mapbox (geokodiranje + radius).

✅ Next.js + Supabase SSR ✅ RLS + migrations ✅ Storage + signed URL ✅ OTP + Resend ✅ Turnstile (opciono) ✅ Mapbox (opciono)

Brzi sadržaj

1) Lokalno 2) Supabase 3) Google login 4) SQL migracije 5) Resend (OTP) 6) Storage + signed URL 7) Turnstile CAPTCHA 8) Mapbox geokodiranje 9) Vercel deploy 10) Gmail API (opciono)

1) Lokalno pokretanje

  1. U root folderu projekta instaliraj pakete: 
    npm i
  2. Napravi fajl .env.local po uzoru na .env.example i popuni vrednosti (u nastavku).
  3. Pokreni dev server: 
    npm run dev
  4. Otvori: 
    http://localhost:3000

2) Supabase projekat

  1. Otvori Supabase dashboard → klikni New project.
  2. Unesi ime, lozinku za DB, izaberi region → klik Create new project.
  3. Levo u meniju: Project Settings → API.
  4. Kopiraj:
    • Project URL → NEXT_PUBLIC_SUPABASE_URL
    • anon public key → NEXT_PUBLIC_SUPABASE_ANON_KEY
    • service_role key → SUPABASE_SERVICE_ROLE_KEY server-only

3) Google login (Supabase Auth)

obavezno — aplikacija koristi Google login preko Supabase Auth.

  1. Supabase → Authentication → Providers → Google → uključi Enable.
  2. Otvori Google Cloud Console → APIs & Services → Credentials.
  3. Klik Create Credentials → OAuth client ID → Application type: Web application.
  4. Dodaj Authorized redirect URIs: 
    http://localhost:3000/auth/callback
https://<tvoj-domain>/auth/callback
  5. Sačuvaj → kopiraj Client ID i Client secret.
  6. Vrati se u Supabase Google provider i nalepi Client ID/Secret → Save.

4) SQL migracije (schema + RLS + RPC)

  1. Supabase → SQL Editor → New query.
  2. Otvori u projektu fajl i izvrši ga jednom: 
    supabase/migrations/0001_init.sql
    (šema, RLS, triggeri, rate limit i geo RPC su u jednom fajlu.)
  3. Klikni Run.

Nakon ovoga tabele, RLS politike, rate limit i radius RPC su spremni.

5) Resend (OTP email)

OTP verifikacija profesionalnog upravnika koristi Resend (ne Gmail API).

  1. Napravi nalog na Resend i uzmi API key.
  2. Verifikuj sender/domain u Resend-u i izaberi From adresu.
  3. U .env.local dodaj: 
    RESEND_API_KEY=...
RESEND_FROM_EMAIL="Zgradonacelnik <noreply@tvoj-domen.rs>"

6) Storage + signed URL download

Dokumenta se uploaduju server-side i čuvaju u Supabase Storage bucket-u.

  1. Supabase → Storage → Create bucket.
  2. Bucket name: npr. zgradonacelnik-private → Private.
  3. U .env.local dodaj: 
    SUPABASE_STORAGE_BUCKET="zgradonacelnik-private"
SUPABASE_SERVICE_ROLE_KEY=...
  4. U aplikaciji: /zgrade/[id]/dokumenta ima dugme Preuzmi koje koristi signed URL endpoint.

7) Turnstile CAPTCHA (opciono, preporučeno)

Ako postaviš Turnstile secret, captcha se proverava server-side na OTP, recenzije, objave, predloge i komentare.

  1. Cloudflare dashboard → Turnstile → Add site.
  2. Kopiraj Site key i Secret key.
  3. U .env.local dodaj: 
    NEXT_PUBLIC_TURNSTILE_SITE_KEY=...
TURNSTILE_SECRET_KEY=...

8) Mapbox (opciono: geokodiranje + radius)

  1. Mapbox account → Tokens → uzmi Access token.
  2. U .env.local dodaj: 
    MAPBOX_ACCESS_TOKEN=...
  3. Kreiraj zgradu kroz /dashboard/moje-zgrade/nova — backend će pokušati da upiše latitude/longitude.
  4. Testiraj radius pretragu na /pretraga/mapa.

9) Deploy na Vercel

  1. Vercel → klik New Project → importuj Git repo.
  2. U Environment Variables dodaj sve iz .env.local: 
    NEXT_PUBLIC_SITE_URL=https://<tvoj-domain>
NEXT_PUBLIC_SUPABASE_URL=...
NEXT_PUBLIC_SUPABASE_ANON_KEY=...
SUPABASE_SERVICE_ROLE_KEY=...
SUPABASE_STORAGE_BUCKET=...
RESEND_API_KEY=...
RESEND_FROM_EMAIL=...
NEXT_PUBLIC_TURNSTILE_SITE_KEY=... (opciono)
TURNSTILE_SECRET_KEY=... (opciono)
MAPBOX_ACCESS_TOKEN=... (opciono)
  3. Deploy → posle deploy-a proveri Google OAuth redirect URI da sadrži produkcioni domen: 
    https://<tvoj-domain>/auth/callback

10) Gmail API (opciono)

napomena Trenutni kod ne koristi Gmail API. OTP email ide preko Resend (jednostavnije, stabilnije za MVP).

Ako želiš kasnije Gmail API (npr. slanje mailova sa tvog Google naloga), treba dodati novu implementaciju slanja emaila i OAuth tok (ili service account).

  1. Google Cloud Console → APIs & Services → Library → enable Gmail API.
  2. Credentials → napravi OAuth client + consent screen.
  3. Implementirati u kodu novi mail provider (nije u ovom MVP-u).
